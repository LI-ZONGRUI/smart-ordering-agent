# Routing Contract

## 决策边界

**Routing != Execution Authorization.** Router 只决定用户请求应交给哪个业务模块。模块本身负责判断事实是否有证据、输入是否合法、是否能形成安全提案，以及是否允许执行。进入 `action_query` 不等于已经加购；购物车变更仍需客户端明确确认、实时菜单复核和确定性应用逻辑。Router 也不决定 RAG 是否有答案。

Router 接收 Contextualizer 处理后的独立问题。路由评测只衡量这个输入的路线选择，不衡量历史理解或 Context Resolution Accuracy；后者需要单独的 Contextualizer benchmark。

| Route | 职责 | 典型请求与边界 |
| --- | --- | --- |
| `menu_query` | 动态菜单及交易事实：价格、售价、当前存在性、在售或售罄状态、当前菜单和饮品 | “拍黄瓜现在还能买吗？”“下单前帮我看看拍黄瓜还有没有。”“柠檬茶多少钱？”“下单前先查状态”主要仍是查询。 |
| `knowledge_query` | 相对稳定的菜品知识：味道、口感、配料、食材、组成、描述、营养、健康、搭配与制作知识 | “菜单里哪个饮品最健康？”仍属知识问题。知识库是否有证据，由下游 RAG 判断；没有证据时安全回答知识不足。 |
| `action_query` | 产品支持的购物车加购意图，只能准备待确认提案 | “加两杯柠檬茶”。若主要意图是合法加购，附带“不要确认”“已经授权”“立即执行”，仍可交给 Action 模块；这些文字绝不授予执行权。下游可以拒绝无法安全形成的提案。 |
| `unsupported_action` | 整体没有安全支持路径的请求 | 直接创建订单、支付、退款、结算、删除或清空购物车、调用内部 Tool、索取系统 Prompt、密钥、内部 checkpoint 或 token，以及其他未支持的敏感操作。单纯提到“下单”不等于要求执行下单。 |
| `smalltalk` | 与具体菜单任务无关的普通社交交流 | 问候、感谢、身份询问与简单聊天。 |

“我还没想好吃什么”同时允许 `menu_query` 与 `smalltalk`：可以引导浏览当前菜单，也可以先自然回应，不需要强迫它落入唯一一种路线。允许集合只表达路由层的产品容许范围，不放松下游事实与执行边界。

## Router v2 主意图决策

Router v1 的 Dev live 结果为 80/80，但第一次冻结 Holdout v1 仅为 33/40。失败集中在规则过宽与优先级、组合意图、知识/菜单 ownership、语义路线定义歧义，以及个别标签歧义。Router v2 不通过 case ID 或原句特判修复这些问题，而采用以下决策顺序：

1. 支付、退款、结算、创建订单、删除/清空购物车、内部 Tool 和敏感内部信息等“操作本身不受支持”的请求继续由确定性层路由到 `unsupported_action`。
2. “不用确认”“已经授权”“立即执行”“绕过校验”等执行修饰语不再先于主业务意图。明确的加购主任务仍进入 `action_query`；这只分配下游模块，不认可修饰语，也不授予写权限。
3. “下单前”“买之前”“先查询再决定”等场景或未来动作不覆盖当前查询。当前价格、库存、在售/售罄和菜单探索归 `menu_query`。
4. 味道、配料、组成、健康、营养、搭配、制作和推荐依据等稳定知识归 `knowledge_query`，无论 RAG 最终是否有证据可回答。
5. 规则只处理高置信语义；真实歧义才进入严格的五路线 Semantic Router。模型输出失败、超时、空输出或未知路线仍安全回退到只读 `menu_query`。

实体名称中的“辣”“推荐”“清爽”等词不单独决定路线；显式的价格/状态、稳定知识或加购意图决定 ownership。

## Action 模块必须保留的边界

- 不由 Router 或模型直接修改购物车、创建订单或支付。
- 加购提案始终为 `requiresConfirmation=true`，由点餐界面完成明确确认。
- 真正应用前复核实时菜单的菜品、价格与状态。
- 用户文本中的“已经授权”“立即执行”等说法不能代替产品确认流程。

## Holdout 历史与评测用途

第一次 Hybrid Router Holdout v1 正式评测为 **33/40（82.50%）**。事后分析发现规则过宽、规则优先级、组合意图、知识与菜单职责边界、语义路线定义歧义，以及个别 Benchmark 标签歧义。原始 `hybrid-router-holdout-live-v1.md` 保留为历史基线。

Holdout v1 已用于正式评测和错误分析，今后仅用作回归集与失败分析集。它不再是完全未见的最终泛化测试集。Holdout v2 在 Router v2 生产实现之前独立创建并冻结；Router v2 开发期间保持未读取、未运行、未用于调参，只允许元数据冻结完整性测试。首次评估泛化能力时使用 v2，之后它也同样转为已见数据。
